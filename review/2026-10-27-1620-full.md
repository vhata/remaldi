select a previously classified Private UI target, and a verified P3 tooling
defect blocks the secret audit on particular valid filenames. Both are
promoted to independent implementation work. The two existing P3 malformed

## Invariants

- An explicit target resolves to that target or fails before dispatch;
  only an omitted target selects the privileged UI context.
- A UI target positively classified as incognito must remain ineligible
  for default selection when discovery changes. The documented shortcut
  for a sole unclassified candidate is a separate compatibility policy.
- Client and daemon resolve one absolute runtime location before choosing
  locks, socket paths and the child's directory.
- Uncertain transmissions are never replayed. Complete-operation deadlines
  include queueing, and cancelled queued mutations cannot execute later.
- Snapshots are derived state, bounded by TTL and invalidated by connection
  changes, raw operations and supported browser events.
- Friendly dispatch follows the committed command policy and validates the
  chosen window in the same browser evaluation as the dispatch. Window
  listing and mutations share their production default-selection rule.
- Optional capability failures remain explicit; malformed upstream values
  should become structured errors rather than uncaught Python exceptions.
- Secret-audit identities preserve full filename contexts. Publication
  tolerates concurrent worktrees, and current path framing must preserve
  the exact filenames that the inventory reports.
- Synthetic checks prove local logic only. Live effects, profile data and
  browser lifecycle remain outside them unless separately authorized.

## Findings

### Open and Moved

- `known-incognito-single-target-selected` — **A known Private target can become the default UI target.** Bug · Open · Verified.
  - Where: `remaldi/browser.py:134` (`Browser._select_ui`, sole-candidate
    return at line 135) at the reviewed commit.
  - Severity: P2.
  - With synthetic Private and regular UI targets, the first refresh caches
    incognito `true` for the former and selects the latter. Remove only the
    regular target from discovery and refresh: the single-candidate return
    bypasses the cached classification, selects the Private target and
    routes a subsequent default `Runtime.evaluate` request to it. A local
    fake WebSocket server received that request on its Private fixture
    endpoint. Honor a known incognito classification even if retaining the
    documented unclassified-single-target compatibility shortcut. This is
    synthetic routing evidence, not an observed live Private-window change.
  - Review backlog: `exclude-known-private-ui-target`

- `secret-audit-current-path-quoting` — **Valid current filenames can crash the mandatory secret audit.** Tooling · Open · Verified.
  - Where: `scripts/audit-secrets.py:48` (`working_files`).
  - Severity: P3.
  - The NUL-delimited file inventory is joined with raw newlines for
    `git hash-object --stdin-paths`, whose unusual paths require quoting.
    In a disposable repository with an empty initial commit, stage a clean
    file named `nested/line\nconfig.py` (a literal newline) or `"config.py`
    (a leading double quote), then run the audit using its absolute path.
    Each audit exits 1 with an uncaught `CalledProcessError` from Git exit
    128 and no JSON report; an ordinary `config.py` control exits 0. Quote
    that input correctly or hash exact paths through an argument-safe
    mechanism. This blocks hooks/the shared gate; it does not demonstrate
    a credential disclosure or a successful audit with missed findings.
  - Review backlog: `quote-current-secret-audit-paths`

- `malformed-service-reply-escapes-client` — **Malformed service replies still escape as uncaught Python errors.** Bug · Open · Verified.
  - Where: `remaldi/client.py:35` (`exchange`), with unchecked fields at
    lines 38-44.
  - Severity: P3.
  - A temporary Unix-socket server reads one request and replies `[]\n`.
    Calling `exchange(path, "status")` still raises `AttributeError` at
    `response.get`. Missing object fields also remain unchecked. Validate
    the envelope and return `protocol_mismatch`; a broken or mismatched
    service is required, since the maintained daemon does not emit this.
  - Existing TODO: `client-malformed-response-errors`; inventory only.

- `malformed-devtools-payloads-escape-boundaries` — **Malformed DevTools payloads still escape structured-error handling.** Bug · Open · Verified.
  - Where: `remaldi/adapter.py:366` (`VivaldiAdapter.evaluate`),
    `remaldi/browser.py:177` (`Browser._probe_incognito`) and line 210
    (`Browser._connection`), `remaldi/transport.py:34` (`CDPConnection._read`)
    and line 76 (`request`).
  - Severity: P3.
  - Synthetic evaluation results with `result: null`, `7`, `"value"` or
    `["value"]` raise `TypeError` instead of `unsupported_result`. A fake
    WebSocket returning top-level `result: []` for the first incognito
    probe still makes refresh report `endpoint_unavailable` and prevents
    probing the valid regular candidate. Unchecked transport/hook shapes
    remain visible by inspection. Validate decoding boundaries and preserve
    capability/protocol errors. No malformed live Vivaldi reply was seen.
  - Existing TODO: `non-object-devtools-results`; inventory only.
